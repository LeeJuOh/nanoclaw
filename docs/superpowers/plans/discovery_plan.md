# Discovery Plan: LinkDive — AI Second Brain

**Date**: 2026-03-13
**Product Stage**: New (개인 사용 검증 → 서비스화)
**Discovery Question**: 에이전트가 내 지식 저장소를 능동적으로 활용하면 저장의 가치가 발생하는가?

---

## 1. 제품 비전

**OpenClaw Second Brain 유스케이스를 NanoClaw 생태계에서 구현 + PARA 자동 분류 + 에이전트 능동 활용**

핵심 니즈 2가지:
1. **양질의 정보 캡처 → 유실 방지**
2. **쌓인 지식 기반으로 AI와 사고하기** (아이디어, 질문, 추론)

핵심 차별점 vs Pocket/북마크 앱:
- Pocket: 사람이 다시 찾아와야 함 → 방치
- LinkDive: 에이전트가 vault를 능동적으로 활용 → 사람이 안 와도 가치 발생

핵심 차별점 vs OpenClaw Second Brain:
- OpenClaw: 분류 없음 (검색만)
- LinkDive: AI 자동 분류 → 사용자 승인/수정 (hybrid)

## 2. 전략 전환

"일반 유저 대상 iOS 앱" → **"본인이 첫 유저 (Mac + Claude Code + NanoClaw)"**

- Phase 0: 자기 자신이 첫 유저, 니즈 검증
- 니즈 충족 시: 서비스화 검토 (iOS 앱 등)

이 전환으로 제거/보류된 리스크:
- ~~NanoClaw 설치 진입장벽~~ (본인이 직접 셋업)
- ~~Claude Max $100 수용성~~ (이미 구독 중)
- ~~일반 유저 도달~~ (서비스화 이후 과제)
- ~~Swift+Node.js 2스택~~ → 검증 후 결정. 2스택 부담은 유효하나 니즈 확인 전에 고민할 문제 아님
- ~~시장 commodity화 경쟁~~ (내 지식 베이스는 나만의 것)

## 3. 가설 구조

```
H3' (에이전트가 vault를 쓸모 있게 활용하는가?)
 │
 ├─ Yes → H1 (캡처 습관이 생기는가?) → 본격 빌드
 │         └─ H2' (hybrid 분류가 추론 품질을 높이는가?) → PARA 고도화
 │
 └─ No  → 피봇 (에이전트 활용 방식 재설계 or 프로젝트 재검토)
```

| # | 가설 | 설명 |
|---|------|------|
| **H3'** | 에이전트 능동 활용 | 에이전트가 vault를 능동적으로 활용하면 저장의 가치가 발생한다 |
| **H1** | 제로 프릭션 캡처 | 캡처 프릭션 ≈ 0이면 저장 습관이 생긴다 |
| **H2'** | Hybrid 분류 → 추론 품질 | AI 자동 분류 + 사용자 승인이 에이전트 추론 품질을 높인다 |

## 5. 검증 실험

### 실험 1: H3' — "에이전트가 내 vault를 쓸모 있게 쓰는가?"

> NanoClaw도 iOS 앱도 안 만들고 검증 가능. Claude Code + 마크다운 폴더면 충분.

- **준비물**: 마크다운 폴더 + Claude Code (순정)
- **비용**: 0원 (이미 있는 것)
- **기간**: 1-2주

| 단계 | 할 일 | 기간 |
|------|------|------|
| 준비 | 마크다운 폴더에 평소 저장하던 링크/메모 20-30개를 수동으로 넣기. YAML frontmatter 간단히 (title, url, tags 정도) | 1일 |
| 시뮬레이션 | Claude Code에서 해당 폴더를 작업 디렉토리로 열고, 실제로 vault 기반 질문/작업 수행 | 1-2주 |
| 판단 | 가치가 느껴지는가? | - |

시뮬레이션에서 해볼 것:
1. "이 프로젝트 관련 자료 뭐 있어?" → vault에서 찾아서 답하는가?
2. "지난주 저장한 것 중 아이디어 뽑아줘" → 유용한 아이디어가 나오는가?
3. "A 글과 B 글의 관점 비교해줘" → 교차 추론이 되는가?
4. "이 주제로 글 쓸 건데 참고할 만한 거?" → 맥락 있는 추천이 되는가?
5. 일상 작업 중 자연스럽게 vault를 참조하게 되는가?

**성공 기준:**

| 결과 | 판단 | 다음 행동 |
|------|------|----------|
| 2주간 vault 기반 질문 **10회 이상** 자발적으로 함 | ✅ 강한 신호 | H1 검증 → NanoClaw 캡처 파이프라인 구축 |
| 5-9회, 유용했지만 습관은 안 됨 | 🟡 약한 신호 | vault 구조나 프롬프트 개선 후 1주 연장 |
| 4회 이하, 굳이 vault 안 봐도 됨 | ❌ 실패 | 피봇 — 에이전트 활용 방식 재설계 |

### 실험 2: H1 — "캡처가 쉬우면 습관이 되는가?" (H3' 통과 시)

- **준비물**: NanoClaw + add-telegram 스킬
- **비용**: NanoClaw 셋업 시간
- **기간**: 2주

텔레그램으로 링크 보내기 → NanoClaw가 크롤링+요약+저장 → vault에 쌓이는 루프. 2주간 캡처 빈도와 vault 활용 빈도 추적.

**성공 기준:**

| 결과 | 판단 | 다음 행동 |
|------|------|----------|
| 일평균 2개 이상 캡처 + vault 활용 유지 | ✅ 성공 | H2' 검증 |
| 캡처는 하는데 vault 활용이 줄어듦 | 🟡 부분 | 에이전트 활용 워크플로우 개선 |
| 캡처 자체를 안 하게 됨 | ❌ 실패 | 캡처 UX 재설계 |

### 실험 3: H2' — "PARA 분류가 에이전트 추론을 높이는가?" (H1 통과 시)

- **방법**: A/B 비교
- **기간**: 1주

| 조건 | 구조 |
|------|------|
| A (대조군) | 플랫 구조 — inbox에 다 넣기, 태그만 |
| B (실험군) | PARA 분류 — AI 추천 + 수동 승인 |

같은 질문을 양쪽에 던져서 답변 품질 비교.

## 6. 검색 전략

> 검색 도구는 확정하지 않음. vault 규모에 따라 결정.

| vault 규모 | 검색 방법 | 비고 |
|-----------|----------|------|
| ~300개 | **Claude Code 순정** (Grep + Read) | 충분. 외부 도구 불필요 |
| 500개+ | **MemSearch** (OpenClaw 메모리 추출 라이브러리) 검토 | 경량, 세션/메모리 기능 포함, 파일 와치 내장 |
| 1000개+ or 검색 품질 부족 시 | **QMD** 검토 | 고품질 (쿼리 확장 + 크로스인코더 리랭킹), MCP 퍼스트클래스, ~2GB |
| PDF/긴 문서 추가 시 | **+ PageIndex** 병용 검토 | LLM 추론 기반, 벡터 DB 불필요, 토큰 비용 발생 |

검색 후보 비교:

| | MemSearch | QMD |
|---|---|---|
| 출신 | OpenClaw 메모리 추출 | 독립 (Tobi Lütke) |
| 언어 | Python | Node.js |
| 검색 | 벡터 (RRF) | 벡터+BM25+리랭킹+쿼리 확장 |
| 디스크 | 가벼움 | ~2GB |
| 파일 와치 | 있음 (1500ms) | 서버 모드 |
| 세션/메모리 | 포함 | 검색 전용 |
| MCP | 없음 (hooks) | 퍼스트클래스 (6개 도구) |
